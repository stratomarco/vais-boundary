# v0.12.0-rc4 automated benchmark summary

RC4 automates the frozen fifteen-model LM Studio benchmark without changing the protected system, independent effect verifier or terminal reward. `vais benchmark --all` validates every downloaded Q4_K_M model before execution, loads one exact model/configuration at a time, runs preflight through full stages, stops a failed model, continues the panel, checkpoints hashes and continuously regenerates reports. Repeating the same command resumes verified completed stages.

The live dry run on the target workstation resolved all fifteen frozen model keys at Q4_K_M with sufficient context. It did not load or unload a model. This is infrastructure evidence, not model-security evidence.

Adversarial regression work found a dotted-ID artifact collision in the prototype: treating `qwen3-0.6b-*` as a path with a suffix collapsed the output stem. Artifact extensions now append to the complete canonical stem. Browser-rendered inspection also found and corrected an SVG context/header overlap.

The self-contained HTML report and GitHub SVG put protocol context above the graph. Every percentage has a defined numerator and denominator. Protected violations, utility, attack-added events, target failures and reasoning conformance remain separate, and there is no composite score. A higher utility percentage means more tested attacked workflows completed; it does not mean the model is proportionally more secure.

RC3 Qwen3-0.6B results remain historical. At RC4 release time the automated rows were still pending. The subsequently completed RC4 run is now retained as bounded discovery evidence in the RC5 audit; it is not relabeled as RC5 evidence.
