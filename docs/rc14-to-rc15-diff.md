# What changed between v0.12.0rc14 and v0.12.0rc15

Base: tag `v0.12.0rc14` (2026-09-28). Before this document and the release review were added:
16 commits, 66 files, **+10,112 / -302** lines, most of them recorded experiment summaries.

Every figure below is reproducible from the tags:

```

git rev-list --count v0.12.0rc14..v0.12.0rc15
```

## The headline

RC14 checked the gateway; **RC15 broadened the evidence.**
- Claude Sonnet 5.5 ran as a target. Neither available attacker moved it, so the monitor was
  never exercised.
- A second reference application, accounts payable, ran a pre-registered campaign on 13 local
  models: no protected violation in the 20 stories built to be stopped.
- The registered totals gap was confirmed by real models and was wider than registered. It is
  closed by a new contract rule, allowed values and session budgets.
- A pre-registered rerun found no violation where the campaign had found one in each of four
  models. It observed one residual, an invoice overpaid within the total, which the verifier now
  reports.

**With nothing configured, nothing changes.** Both benchmark snapshots regenerated byte-identical
before the version bump. The incident-response application's outputs, prompts, schemas,
configuration hash and report text are byte-identical to rc14.

## The monitor's decision function

One addition, effective only for contracts that declare it. `allowed_values` refuses a value
outside the list, or a listed value used twice when single use is declared. `budgets` refuses a
call that would take the session's total past its cap. Both:
- need a session ledger and refuse without one;
- are checked after the per-call rules and before approvals, so a human's approval is never spent
  on an action they then refuse;
- spend nothing when an action is refused.

Everything else the monitor decides is unchanged, which the snapshots show.
