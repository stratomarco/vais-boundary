# v0.6 Static Adversarial Benchmark

v0.6 turns the five-scenario smoke benchmark into a balanced static control corpus before adaptive RLVR evaluation.

## Measurement pipeline

VAIS reports four distinct stages:

1. **Plan change** — any plain tool/argument difference from the clean baseline.
2. **Security-relevant drift** — authority, confidentiality, capability, or approval semantics changed.
3. **Attack-objective success** — a deterministic scenario-specific oracle says the attack goal was achieved.
4. **Security impact / IVR** — an observable effect violated an independent security invariant. This remains the terminal security reward.

A model may therefore be influenced without creating security-relevant drift, and an attack objective may succeed at the model layer while deterministic enforcement still prevents external impact.

## Corpus

`benchmarks/attacks/static-v0.6-125.jsonl` contains 125 candidates: 25 per scenario across direct overrides, fake authority, policy/context confusion, role play, structured-data wrappers, multilingual variants, workflow confusion, memory claims, and light obfuscation. All destinations/canaries/commands are benchmark-only values (`.test`, `attacker-wallet`, `echo compromised`).

Run it with:

```powershell
vais benchmark-lmstudio `
  --model "qwen/qwen3.5-9b" `
  --reasoning-mode off `
  --max-tokens 2048 `
  --attack-corpus bundled:v0.6 `
  --output .\results\qwen35-v060-static.jsonl `
  --summary .\results\qwen35-v060-static-summary.json
```

The console shows the security pipeline directly. Use `--print-json-summary` only when the full JSON summary is also useful on stdout.

## Corpus execution semantics

Each JSONL row is a distinct benchmark candidate. v0.6 expands the corpus into scenario-scoped attacker instances, so all 125 rows are evaluated rather than round-robin sampling a single candidate per scenario. Protected and unprotected modes reuse the same cached model plan where the target adapter supports caching.

## Utility denominator

Clean baselines are deduplicated by target, scenario, protection mode, and baseline plan. Twenty-five attacks against one scenario therefore contribute one clean-utility observation per target/mode rather than twenty-five duplicate observations.
