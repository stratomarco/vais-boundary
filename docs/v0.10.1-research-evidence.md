# v0.10.1 — Research Evidence and Measurement Infrastructure

v0.10.1 is a research-correctness patch. It does not change the protected reference monitor, task authority model, information-flow enforcement, tenant checks, exact approvals, declassification semantics, protected invariants or adaptive terminal reward introduced in v0.10.0.

## Why an evidence base

VAIS now has multiple generations of static, MCP, stateful Reference Agent and adaptive experiments. A future paper must be able to distinguish:

- what the raw artifact actually observed;
- what interpretation was drawn from that artifact;
- which later experiment revised an earlier interpretation;
- what scope and limitations bound the claim.

The canonical record therefore lives in Git-reviewable YAML and Markdown. SQLite is only a generated query layer.

## Canonical vs generated data

Canonical:

- `research/knowledge/claims.yaml`
- `research/knowledge/findings.yaml`
- `research/knowledge/decisions.yaml`
- `research/knowledge/limitations.yaml`
- `research/knowledge/hypotheses.yaml`
- `research/knowledge/terminology.yaml`
- `research/knowledge/sources.yaml`
- `research/narrative/*.md`

Generated:

- `research/db/vais-research.sqlite`
- `research/evidence/artifact-index.jsonl`
- `research/evidence/experiment-index.jsonl`
- `research/evidence/observation-index.jsonl`
- `research/evidence/build-manifest.json`

The generated database stores hashes and indexes; the raw experiment JSONL remains the source evidence.

## Historical ingestion

`vais research-build --history-root <path>` inspects only immediate VAIS version directories such as `vais-v03`, `vais-v09` and `vais-v0.10`. It deliberately does not recursively walk every unrelated directory on the drive.

Repeated `--root` can index explicit files or directories.

## Measurement additions

Adaptive summaries now expose:

- off-objective security-event episodes;
- matched utility transitions (control success/failure vs attacked protected success/failure);
- pair-delta unavailable episodes;
- logical target status counts;
- truncation attempts and recovery;
- physical generation attempt counts;
- output/reasoning token totals;
- latency p50/p95/max.

These additions were motivated by the Qwen and Gemma v0.10 empirical runs. In particular, aggregate protected utility was insufficient for attribution, and Gemma length truncation required explicit generation-budget accounting.

## Fixed-search ablation

`--search-mode fixed` retains the deterministic mutation operator schedule and episode budget but always applies post-exploration mutations to the original seed. The normal `adaptive` mode can select the strongest prior candidate as parent. Comparing the two under identical target/model configuration is the intended ablation for feedback-guided search.

## Truncation recovery

`--target-truncation-retry-tokens N` enables one explicit retry only when a reference-agent target generation ends with a length/max-token truncation. The first failed attempt remains in `attempt_history`; a recovered generation is therefore auditable rather than silently rewritten as a first-pass success.

The option is disabled by default so existing v0.10.0 experiments remain directly reproducible.
