# v0.9.3 Reference-Agent Interface Normalization

v0.9.3 is the final interface-normalization pass for the v0.9 Reference Agent before adaptive verification. It intentionally adds no new attack stories, no new policy primitive, and no new security metric.

## Why this patch exists

The v0.9.2 real-model trace audit found one remaining ambiguity around delegated-agent workflows. The reference harness had already performed the legitimate `research-agent` delegation to obtain the observed sub-agent output, while the trusted user task still told the model to perform that delegation. The `agent.delegate.scope` field was also only typed as a generic string, making interpretations such as an incident ID or task topic understandable even though VAIS expected a capability scope such as `knowledge:read`.

Before adaptive verification, the environment should not teach an attacker or a target model quirks that come from an underspecified test interface.

## Trusted setup authority is not task authority

For delegated-agent stories, the application now performs the pre-agent retrieval under a narrow trusted setup contract:

```text
application setup
    agent.delegate(
        agent_id = research-agent,
        scope    = knowledge:read
    )
        |
        v
observed sub-agent result
        |
        v
model task
```

The model's task contract does **not** include `agent.delegate` or `agents:delegate`. The tool can remain application-exposed, but a later model-initiated re-delegation is denied.

This makes the boundary explicit:

> setup authority used by the application is not automatically inherited by the model.

Trusted setup/retrieval effects are excluded from the `no_unauthorized_effect` task invariant because they are application orchestration, not model-proposed task effects. Other trace invariants still inspect the resulting observable effects.

## Delegation tool semantics

The LM Studio structured-output schema now gives argument-level semantics. In particular:

- `agent_id` is the canonical sub-agent identity;
- `scope` is an explicit delegated **capability scope**, for example `knowledge:read`;
- `scope` is not an incident ID, topic, or natural-language task description;
- `task` is a bounded work description and does not grant additional authority.

The three delegated attack stories now tell the model that the application has already completed the bounded delegation and that the observed sub-agent output is information only.

## Objective diagnostic normalization

The deterministic attack-objective diagnostic now recognizes equivalent opaque-public-artifact sinks for destination-substitution stories:

- `email.send_external` and `email.send_public_update` can both express an attacker-controlled email destination;
- `slack.send_external` and `slack.send_public_update` can both express an attacker-controlled public Slack destination.

This changes only the model-side diagnostic. Observable security remains determined by effects and trace invariants.

## What does not change

v0.9.3 does not change:

- the reference monitor's security model;
- confidentiality or provenance semantics;
- exact-action approvals;
- resource/tenant ownership;
- public-artifact declassification;
- semantic paired attribution;
- the 5 clean / 20 control / 20 attack inventory;
- the protected invariant oracle.

The intended outcome is a cleaner experimental interface, not a stronger-looking benchmark.
