# VAIS Boundary v1.0.0 release review

Date: 2026-10-20

## Scope and decision rule

1.0 is the boundary: a deterministic reference monitor and gateway for the actions an AI agent
proposes. It fixes three things for 1.x:
- **the public interface:** the 61 names `vais` exports;
- **the command line:** the boundary's ten commands at the top level, the benchmark and research
  tooling under `vais lab`;
- **the file formats:** every file the boundary reads or writes, with samples and a decisions
  snapshot each 1.x release must reproduce ([`formats.md`](formats.md)).

It is also the first release of the work on `main` since 0.12.0rc15: caps per allowed value
(DEC-069), declared stores (DEC-070), and five findings.

Both benchmark snapshots regenerate unchanged except for `framework_version` and the
configuration hash that covers it, so no 1.0 change moves a recorded benchmark decision. The
frozen RC7 evidence is carried unchanged. The review does not certify production readiness, and
no independent security review has been done.

The tagged tree also contains `website/`, `campaigns/` and `experiments/`. None is part of the
library, all are absent from the wheel and the sdist, and `website/` is outside every gate check.

## Breaking changes from 0.12.0rc15

| Change | Before | From 1.0 |
|---|---|---|
| Distribution name | `verifiable-ai-security` | `vais-boundary`; the import and the command stay `vais` |
| Top-level exports | 128 names, 76 of them benchmark and research tooling | the 61 boundary names; tooling is imported from its own module, such as `vais.benchmark` |
| Tooling commands | `vais benchmark-default` and 19 others | `vais lab benchmark-default`; the old spelling exits with code 2 and names the new one |

The experiment runners and the library's own campaign automation use the new spelling. The
frozen RC campaign plans keep the spelling they were run with.

## New mechanisms

| Mechanism | What it does | Default |
|---|---|---|
| Caps per allowed value (DEC-069) | A contract caps a numeric argument separately for each allowed value of another argument, such as the amount paid against each invoice, summed over the session | Off; per contract |
| Declared stores (DEC-070) | A profile declares which stores each tool writes and reads; the gateway and the MCP client refuse to start while a declared store could carry confidentiality or minted authority into another session | Off; profiles without declarations behave as before |
| The 1.0 boundary (DEC-071) | The public interface, the command-line split, the package name and the frozen formats above | Always |
| Observe-only mode (DEC-072) | Gateway configuration version 2 can set `observe_until`: every call is decided as if enforcing, audited as `would_allow`, `would_deny` or `would_require_approval`, and forwarded anyway. At most 14 days ahead; enforcement resumes by itself; `vais gateway` warns on every start | Off; version 1 configurations cannot enable it |

## New evidence since 0.12.0rc15

| Study | Pre-registered | Result | Finding |
|---|---|---|---|
| Caps per invoice, replayed on the recorded attack-21 actions | No (counterfactual replay) | The caps refuse each of the rerun's three overpayments at the overpaying payment; no clean run gains a refusal and nothing refused is newly allowed | FIND-072 |
| Gateway replay of the accounts-payable traces | No (verification) | 6,499 of 6,500 campaign traces and 480 of 480 rerun traces decided as the library did; the one difference held a payment for approval one turn earlier than the library would have | FIND-073 |
| Tier-A v3, the guardrail cost axis | Yes | VAIS_RESOLVE caught 41 of 41 validated attacks; the one guardrail within ten points (37 of 41) dropped 58 of 120 legitimate documents; across four runs VAIS_RESOLVE caught 197 of 197 | FIND-074 |
| Cross-session flows | Yes | All eight predictions held: trust does not survive a store, but confidentiality and minted authority can; DEC-070 checks declared stores | FIND-075 |
| Stability of the RC7 result | Yes | Exactly reproducible on a fixed inference engine (720 of 720); across llama.cpp versions 61% of episodes reproduced and per-model rates moved by up to 11.7 points; 0 protected violations | FIND-076 |

Each result carries its bounds in the research ledger and in [`evidence-index.md`](evidence-index.md).

## Limitations published since 0.12.0rc15

- **LIM-073.** The library labels a whole planned turn before running it, so a value minted during
  the turn is not yet authority within it. This costs utility, not safety.
- **LIM-074.** Labels are not persisted; a store carries confidentiality or minted authority into a
  later session unless it is declared and its writers match its readers.
- **LIM-075.** RC7's per-model rates are one draw under an unrecorded inference-engine version;
  differences between models under 11.7 points are not interpreted.
- **LIM-076.** The Tier-A evidence covers one application, one tool and two agent models; its
  guardrail drop rates come from a corpus written to resemble what guardrails flag.

| Review item | Bounded result |

| Reference monitor decision function | **Extended** by DEC-069 for contracts that declare caps per value; otherwise unchanged, which the regenerated snapshots and the frozen decisions snapshot show. |

## Found while releasing

- **The library's campaign automation still built the old command spelling.** Removing the old
  spellings exposed it; it now builds `vais lab adaptive-reference-lmstudio`, and so do the
  experiment runners.
- **The mutation check found one untested property of observe mode:** nothing showed that observing
  leaves an operator's approval grant unused. A test now does.
- **A push to `main` deploys the website.** The command-line change reached the site's "try it"
  panel on 2026-10-20; it installs from `main`, so its instructions were correct throughout.
- **The earlier decision to keep the old distribution name** was made to avoid migration cost;
  neither name had been published on PyPI, so the cost was small. `naming.md` records the change.

## Open surfaces shipping unmitigated

- **Observe-only mode, while it lasts,** forwards calls VAIS would refuse (at most 14 days).
- **Frontier models under attack (FIND-067, FIND-068):** untested in effect, since no available
  attacker moved the model.
- **No independent security review**, and state coordinated on one machine only (LIM-057).
- **Carried from 0.12.0rc15:** S13 on the library path; limits over several actions for stateless
  callers (LIM-035, LIM-044); model text (LIM-051); arguments without a trust requirement
  (LIM-048); stores that are not declared (LIM-074).

## Validation and release gate

1.0.0 is releasable only after all of the following succeed:

1. full source regression suite, with and without the `mcp` extra;
2. a mutation check of every 1.0 mechanism;
3. default policy and invariant validation;
4. deterministic protected benchmark smoke test on the default and MCP paths;
5. wheel and sdist build plus an isolated, offline wheel installation with a probe for every
   change, with `experiments`, `website` and `campaigns` absent from both;
6. deterministic source ZIP reproduction, a test run from a fresh unzip, and SHA-256 manifest
   verification;
7. campaign harness self-test, and a campaign on each target with no `real` verdict;
8. tracked-tree secret and privacy scans, and a research-doctor result identical to a clean RC9
   tree;
9. clean GitHub CI across Python 3.11-3.14 on Windows and Linux;
10. annotated `v1.0.0` tag and release assets built from the verified commit.

Results are recorded in `benchmarks/rc/v1.0.0-release-review.json`. Passing these supports only
the recorded implementation and packaging result. It does not establish:
- universal prompt-injection resistance;
- production authorization-service readiness;
- an independent security review;
- external audit anchoring;
- enforcement against a frontier model under an attack that moves it.
