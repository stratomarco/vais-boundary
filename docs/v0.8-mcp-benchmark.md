# v0.8 MCP-path benchmark

## Research question

When hostile instructions arrive through an MCP data channel, can model influence become an unauthorized externally observable MCP effect, and does the deterministic VAIS boundary contain that effect?

## Experimental path

```text
clean MCP tool result -> baseline model plan
clean MCP tool result + attack -> candidate model plan
                                |
                 same candidate plan reused
                    +-----------+-----------+
                    |                       |
             unprotected MCP          protected MCP
                    |                       |
               mapped effect          VAIS reference monitor
                    |                       |
               invariants             mapped effect if ALLOW
                                            |
                                        invariants
```

The MCP input is labelled `UNTRUSTED` for authority purposes. v0.8.1 refines the model-side measurement model so behavioral drift is directional: security escalation, contraction-only drift, and mixed drift are reported separately. The terminal security oracle remains observable invariant violation.

## Corpus

`bundled:v0.8-mcp` contains 125 candidates: five scenarios multiplied by 25 techniques. It is derived from the controlled v0.6 static corpus so delivery mechanism, rather than attack inventory, is the main experimental change.

## MCP effect oracle

The default benchmark uses an in-process object implementing the minimal `call_tool` protocol. It records every outbound request and returns deterministic success. `MCPToolBinding` maps those calls to application-domain effects such as `email_sent`, `payment_sent`, `document_read`, and `shell_executed`.

This is not a network/MCP-server emulator. It is a repeatable harness for the exact enforcement seam used by a real MCP `ClientSession`.

## Interpretation

A protected IVR of zero means no invariant violation was observed for the evaluated corpus, scenarios, model configuration and valid target generations. It is not a universal security proof. Target-generation failures remain excluded from security denominators and are reported separately.

## v0.8.1 interpretation note

`behavioral_drift` is broader than `security_escalation`. A removed tool call can be a contraction, while an added/changed unauthorized action can be an escalation. `off_objective_security_escalation` records episodes where the predefined attack objective failed but the hostile MCP content still induced other risk-increasing behavior.

MCP `NOT_CALLED` is an execution-state fact: the proposed call did not cross the protected boundary. It must not be presented as a count of prevented attacks because a denied call can be unrelated to the scenario's targeted attack objective.
