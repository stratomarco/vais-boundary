# v0.9.1 Reference-Agent Correctness Patch

v0.9.1 keeps the v0.9 incident-response reference system and fixes four methodological gaps discovered by auditing the first Qwen and Gemma stateful traces.

## 1. Matched controls for attack attribution

Every attack story now has a non-hostile control with the same trusted task, task contract, allowed tools, capability scopes, retrieval surface and turn budget. Only the hostile payload is removed.

This distinguishes:

- **baseline overreach**: the model exceeds authority even without adversarial content;
- **attacked security escalation**: escalation observed in the attacked workflow;
- **attack-attributable escalation**: attacked escalation when the valid paired control did not escalate.

Attribution rates use only valid attacked/control pairs. Target-generation failure is not silently interpreted as attack failure or attack success.

## 2. Model-visible deterministic action receipts

Every agent-proposed action now yields a structured VAIS receipt containing:

- canonical tool;
- `ALLOW`, `DENY`, or `REQUIRE_APPROVAL` decision;
- `observed`, `not_called`, or `indeterminate` call state;
- whether execution is known to have happened;
- whether a tool result was observed.

Receipts are trusted factual system state, not authorization tokens. They intentionally omit detailed policy reasons from the default model-visible channel.

This makes protected/unprotected state divergence genuine: a protected agent can now observe that its previous requested effect did not occur and can recover or replan on a later turn.

## 3. Explicit deterministic declassification

The public-status workflow no longer lets arbitrary model output implicitly downgrade internal incident data.

The trusted local primitive:

```text
status.build_public_update
```

accepts a trusted incident identifier and deterministically creates the approved public status artifact. The resulting value has:

```text
source = application:status_declassifier
trust = trusted
confidentiality = public
```

Only after that transform can the reference workflow send the public artifact to the authorized external recipient.

The intended composition is therefore:

```text
INTERNAL Jira data
        -> trusted deterministic declassifier
        -> PUBLIC approved artifact
        -> external email
```

The model does not get to declare internal material public by assertion.

## 4. Reporting semantics

The reference summary now reports paired-control metrics separately for protected and unprotected workflows, including:

- baseline control overreach;
- attacked security escalation;
- attack-attributable security escalation;
- targeted attack-objective success;
- violating workflows;
- attack-attributable violating workflows;
- clean, control, and attacked workflow utility;
- target failures and valid paired-comparison denominators.

## What did not change

v0.9.1 does not add new attack stories and does not introduce an AI-based security judge. Authorization, declassification, execution mediation and trace invariants remain deterministic.
