# VAIS Boundary v0.12.0rc11 release review

Date: 2026-09-22

## Scope and decision rule

RC11 is a hardening release. Where RC10 carried one change to library behaviour, RC11 carries
four modules' worth, because the enforcement layer was put under adversarial test for the first
time and three defects fell out. It also adds one new invariant type, in response to a gap an
external reviewer found in the central property.

The frozen RC7 benchmark evidence is carried unchanged and RC11 makes no new model claims from
it. The review does not certify production readiness and does not extend any benchmark claim.

The tagged tree also contains `website/` and `campaigns/`. Neither is part of the library, both
are absent from the wheel and the sdist, and `website/` is outside every gate check below.

## Material findings, fixed

### FIND-046: a spent approval could replay after a failed write

`ApprovalStore.consume` marked a grant spent in memory and then persisted it. When the write
failed, on a full or read-only volume, memory said spent and the stored record said unspent. The
call itself failed closed, because the error propagated instead of returning an authorization, so
nothing executed. But the next process to load the store read the grant as unspent and consumed
it again. **Consume-once, which this project states as a property and tests for, did not survive
a failed write across a restart.**

The in-memory change and the persist are now applied together, rolling the in-memory change back
if the write fails, so the stored record is never less restrictive than memory. The handler
catches broadly and re-raises, converting no fault into a silent decision, so it does not
contradict DEC-033 (DEC-038). Reverting the fix fails the regression test.

### FIND-047 and FIND-048: three loaders broke their own rejection contract

Found by the continuous campaign within an hour of it first running, and both the same class: a
validator assuming YAML hands it a string.

`default_action` was tested with set membership and no type guard. Set membership raises
`TypeError` for an unhashable operand, so `default_action: [allow, deny]` failed with "unhashable
type" instead of `PolicyValidationError`. The version check on the line above already carries the
`isinstance` guard and short-circuits correctly; this one did not.

The unknown-field reporter sorted and joined YAML keys directly. YAML keys are not necessarily
strings, so an integer, boolean, null, float or date key raised `TypeError` instead of being
reported. That helper is copied verbatim into the policy, invariant and MCP loaders, so the same
latent fault existed three times and is fixed in all three.

Neither was a bypass. Both failed closed by exception. Both broke the declared contract that
malformed input is rejected as `PolicyValidationError`, and an application catching that to
degrade gracefully would have missed them (LIM-039).

### FIND-043: the volume half of composition was not expressible

An external reviewer reported that the central property, stated over "an unauthorized externally
observable effect" in the singular, covers only one half of composition. The flow half, a secret
read followed by a public send, was already expressible through trace-level invariants. The
volume half, N individually authorized effects whose count is the problem, was not expressible at
all, because the policy schema is a closed allowlist that would have rejected a cardinality field
at load. Every code claim in that report was verified before it was accepted.

`max_effect_count` closes this **in VERIFY only**. See the open surfaces below.

## Negative results, recorded because they are evidence too

**FIND-044, the provenance lattice.** Tested against its own docstring rather than its
implementation, with expected labels written from the stated rule and applied to seeded DAGs of
depth at least twelve. No laundering path was found through derivation. Five mutations of the
lattice rules were each caught, so the tests are known to be capable of failing. What the work
surfaced is an asymmetry rather than a bug: integrity defaults to the cautious end of the lattice
and confidentiality defaults to `public`, its bottom (LIM-036).

**FIND-045, the audit chain.** Fork, truncate, splice and reorder were run against it. The
detection boundary is not drawn by which manipulation is used but by whether the attacker
recomputes the chain afterwards, which needs only public SHA-256 because the chain holds no key
(LIM-037, LIM-038).

## Security-boundary review

| Review item | Bounded result |
|---|---|
| Approvals | **Changed.** Consume-once now survives a failed persist. Identity scoping, consume-once semantics and concurrency behaviour are otherwise unchanged from RC10. |
| Config loading | **Changed.** Three loaders now reject non-string input types in contract rather than raising `TypeError`. No schema semantics changed; strictly more inputs are rejected cleanly. |
| Invariants | **Extended.** One new type, `max_effect_count`, the first whose subject is the effect set. The five existing types are unchanged. |
| Canonicalization | Unchanged from RC10 and re-tested: 217,000 executions per seed against `deep_freeze` and `action_fingerprint` produced no fault. |
| Provenance lattice | Unchanged, and now property-tested. Sound through derivation; see LIM-036 for the confidentiality caveat. |
| Audit | Unchanged. Hash chained, not externally anchored, and the boundary of that is now demonstrated rather than asserted. |
| Reference monitor, policy semantics, MCP | Unchanged from RC10. |

## Open surfaces shipping unmitigated

Two, both named rather than buried.

**S13, the decision-reason output channel.** Unchanged from RC10. Reason strings returned to the
caller name the argument a contract binds. Recorded as open with a proposed direction.

**S14, the ENFORCE half of volume composition (LIM-035).** `max_effect_count` detects a breach
after the fact. It does not deny the action that would cause one, because the reference monitor
takes a single action and holds no state across decisions. Enforcing in flight would change the
signature of the central security function and require every adapter to thread a counter, which
is the same obligation LIM-033 shows adapters can drop silently. No date is promised, and
`tests/test_invariant_cardinality.py` asserts the limitation so it stays visible.

## Validation and release gate

RC11 is releasable only after all of the following succeed on the final commit:

1. full source regression suite;
2. default policy and invariant validation;
3. deterministic protected benchmark smoke test;
4. wheel and sdist build plus isolated wheel installation, with `experiments`, `website` and
   `campaigns` absent from both;
5. deterministic source ZIP reproduction and SHA-256 manifest verification;
6. campaign harness self-test, and a campaign on each target with no `real` verdict;
7. tracked-tree, archive and reachable-history privacy and secret scans;
8. clean GitHub CI across Python 3.11-3.14 on Windows and Linux;
9. annotated `v0.12.0rc11` tag and release assets built from the verified commit.

Passing these supports only the recorded implementation and packaging result. It does not
establish universal prompt-injection resistance, production authorization-service readiness,
external audit anchoring, or any general claim about content-filtering defences.
