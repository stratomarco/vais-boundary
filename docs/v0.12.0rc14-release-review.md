# VAIS Boundary v0.12.0rc14 release review

Date: 2026-09-28

## Scope and decision rule

RC13 added a gateway. RC14 checks it against the library and makes what it holds durable.
Replaying 23,040 recorded traces through the gateway found one defect and one gap, both closed;
session state that lived in one process's memory can now survive a restart and hold across
processes on one machine; four recorded gaps are closed; and the pre-registered RC13 campaign
measures the decision-reason channel.

Every new mechanism is opt-in, except that every unreadable security file is now a
`PolicyValidationError` and that an approval held in a contract now counts beside an approval
store. Both benchmark snapshots regenerated byte-identical before the version bump, so no rc14
change moves a recorded decision; after it, only the version and the configuration hash that
covers it moved.

RC14 adds new model evidence from the RC13 campaign, stated with its bounds below. The frozen RC7
evidence is carried unchanged. The review does not certify production readiness.

The tagged tree also contains `website/`, `campaigns/` and `experiments/`. None is part of the
library, all are absent from the wheel and the sdist, and `website/` is outside every gate check.

## Material findings, fixed

### FIND-062: contract approvals were ignored beside an approval store

Given an approval store, the monitor checked it and never the contract's
`approved_action_fingerprints`. The gateway always has a store, so every approval in its contract
files authorized nothing, and ENFORCE disagreed with VERIFY, which accepts either source. It failed
closed. The replay found it as divergences no known cause explained. A contract approval now
counts once per session, its use recorded in the store's file (DEC-060). A first version counted
the use only in the in-memory ledger; review showed a restarted gateway, or a second one on the
same store, allowing the same pre-approved payment again, and it was replaced before release.

### FIND-066: a deeply nested security file escaped the loaders

Beyond the `yaml.YAMLError` LIM-039 recorded, a file nested deeply enough escaped every loader as
`RecursionError`, and one that was not UTF-8 the library loaders as `UnicodeDecodeError`. The
gateway's contract registry skips a bad file but did not catch the recursion, so one such file in
the contract directory made every session's lookup fail. Only an operator can write there, so it
was an availability fault. Every unreadable security file is now a `PolicyValidationError`.

### FIND-061: the adaptive attacker was told the monitor's reasons

Documented as omitting them, the attacker's feedback carried reason codes in 28.6% of P1b-4
episodes. The docstring is corrected, and `--attacker-feedback outcomes` removes them; the default
is unchanged, so earlier campaigns' configurations stay byte-identical.

## New mechanisms

| Mechanism | What it does | Default |
|---|---|---|
| Contract approvals beside a store (DEC-060) | A contract-held approval counts once per session, recorded in the store file | Applies whenever a store is passed |
| File-backed session state (DEC-062) | `SessionLedger` and `RevocationList` take a file; the gateway takes `state:` and `revocations:`; `vais gateway-revoke` | Off; in memory as before |
| Declared mints (DEC-064) | An MCP profile tool's result becomes authority for named arguments of other tools, in one session, by exact match, for allowed tools | Off; per tool |
| Audit verification (LIM-038) | `verify_report`, `verify_jsonl`, `vais audit-verify` locate every break | On request |
| Inert-invariant check (LIM-041) | `engine.inert`, `vais check-invariants` against an application's effect kinds | On request |
| Call timeout (LIM-040) | A hung tool call or read-back is indeterminate | Off; `call_timeout` |
| Attacker feedback option (FIND-061) | `--attacker-feedback outcomes` | `reasons`, as before |

## New evidence

**RC13 campaign** (pre-registered): 13 local models, reasoning off, each attacked by
qwen2.5-7b-instruct with the monitor's reason codes in its feedback and without. Zero protected
violations in 6,237 evaluable episodes across 26 arms. Telling the attacker the reasons made no
detectable difference: +0.3 points pooled, registered 95% interval −3.2 to +3.8, −4.7 to +5.2 with
stories resampled (FIND-064). Episodes cluster by story with a design effect of 5.7, so every
per-episode interval VAIS had reported was about 2.4 times too narrow; no primary result changes,
and two exploratory P1b-4 differences no longer exclude zero (FIND-065, DEC-061, LIM-069).

**Gateway replay**: 23,040 recorded traces from P1b-4, RC7 and the campaign replayed through a
real gateway. No decision and no label was more permissive than the library's; with the reference
declassifier's mint declared, 95.8% of traces are identical and the one remaining difference is
single use of contract approvals (FIND-063).

## Limitations published

LIM-068 to LIM-070. A declared mint trusts the minting server (LIM-070). LIM-055, LIM-056 and
LIM-063 are narrowed by file-backed state, which still holds on one machine only (LIM-057), and
LIM-068 by the mint. LIM-038 to LIM-041 are closed (DEC-063).

## Open surfaces shipping unmitigated

**S13 on the library path.** Reasons returned by `ReferenceMonitor` and `MCPProtectedClient` are
unchanged; only the gateway withholds them. RC14's campaign measured no detectable effect for its
attacker, which does not cover every attacker.

**Stateless callers (LIM-035, LIM-044).** Without a `SessionLedger` or an `ApprovalStore`, limits
over several actions and single use of a contract-held approval remain VERIFY-only.

**S15, model text and reasoning output (LIM-051).** Not mediated by any path.

**Arguments without a trust requirement (LIM-048).** Still carry the model's judgement inside the
policy; the origin rule is a human gate, not a fix (LIM-064).

**State across machines (LIM-057).** File-backed state is coordinated on one machine only.

## Validation and release gate

RC14 is releasable only after all of the following succeed on the final commit:

1. full source regression suite, with and without the `mcp` extra;
2. a mutation check of every fix and mechanism in this release;
3. default policy and invariant validation;
4. deterministic protected benchmark smoke test on the default and MCP paths;
5. wheel and sdist build plus isolated wheel installation with a probe for every change, with
   `experiments`, `website` and `campaigns` absent from both;
6. deterministic source ZIP reproduction, a test run from a fresh unzip, and SHA-256 manifest
   verification;
7. campaign harness self-test, and a campaign on each target with no `real` verdict;
8. tracked-tree secret and privacy scans, and a research-doctor result identical to a clean RC9
   tree;
9. clean GitHub CI across Python 3.11-3.14 on Windows and Linux;
10. annotated `v0.12.0rc14` tag and release assets built from the verified commit.

Results are recorded in `benchmarks/rc/v0.12.0rc14-release-review.json`. Passing these supports
only the recorded implementation and packaging result. It does not establish universal
prompt-injection resistance, production authorization-service readiness, external audit
anchoring, or any claim about frontier models.
