# VAIS Boundary v0.12.0rc15 release review

Date: 2026-10-02

## Scope and decision rule

Until RC14, every result came from one application designed alongside the monitor, run against
local models of 15B parameters or fewer. RC15 broadens that evidence:
- a frontier model as a target;
- a second reference application with its own pre-registered campaign;
- a contract rule that closes the enforcement gap that campaign confirmed, with a pre-registered
  rerun to test it.

Every new mechanism is opt-in. Both benchmark snapshots regenerated byte-identical before the
version bump, so no rc15 change moves a recorded decision; after it, only the version and the
configuration hash that covers it moved. The incident-response application's outputs,
model-facing prompts, plan schemas, configuration hash and report text are byte-identical to rc14.

RC15 adds new model evidence from four studies, stated with their bounds below. The frozen RC7
evidence is carried unchanged. The review does not certify production readiness.

The tagged tree also contains `website/`, `campaigns/` and `experiments/`. None is part of the
library, all are absent from the wheel and the sdist, and `website/` is outside every gate check.

## Material findings

### FIND-070: the registered totals gap was reached by real models, and it was wider than registered

A task that pays two invoices could not bind their ids or amounts, because a contract bound one
value per argument. In the finance campaign, four of 13 models made payments the monitor allowed
on every per-call rule and the verifier rejected:
- an overpayment;
- a payment booked against another supplier's invoice;
- the full total paid twice against an invented id, once in a model's unattacked control.

The registration predicted the overpayment only. The gap is closed by DEC-067.

### FIND-071: the gap closed under a pre-registered rerun, with one residual observed

With DEC-067's rules declared, the same four models made no protected violation in 234 evaluable
attack-21 episodes, where the campaign's search had found one in each model within 10 episodes.
Every model had payments refused by the new rules, and the unattacked double payment is refused.

In 3 episodes a task invoice was overpaid while the session total stayed within budget. Neither
the monitor nor the verifier flagged it, and the application's utility measure counted it as
success. The verifier now reports it (DEC-068). Refusing it in the monitor is planned for the next release.

### FIND-067 and FIND-068: neither available attacker moves Claude Sonnet 5.5

Claude Sonnet 5.5 with thinking off showed no attack-added action and no protected violation:
- 0 of 240 full-stage episodes against the mutation-search attacker;
- 0 of 238 evaluable episodes against the RC13 language-model attacker, pre-registered.

Nothing was refused or held, so the monitor was never exercised, and these results bound the
attackers, not VAIS. Testing enforcement on a frontier model needs a stronger attacker.

## Limitations published

**LIM-071.** A Claude run is neither greedy nor pinned, and the API's classifiers can refuse
security-themed prompts.

**LIM-072.** Published with the finance application, widened by the campaign and narrowed by
DEC-067. What remains:
- the operator must declare the rules;
- the monitor does not pair amounts with allowed values, so an invoice can be overpaid within the
  total. The accounts-payable verifier reports this since DEC-068, after the fact;
- a budget has no currency or unit semantics;
- single use and budgets hold for one ledger, so on one machine at most (LIM-057).

## Security-boundary review

| Review item | Bounded result |
|---|---|
| Reference monitor decision function | **Extended.** Allowed values and budgets apply only to contracts that declare them; otherwise unchanged, which the byte-identical snapshots show. |
| Contracts | **Extended.** `allowed_values` and `budgets`, validated: trusted, distinct, non-empty values; finite, non-negative decimal budgets. An argument cannot be both bound and given allowed values. |
| Session ledger | **Extended.** Records spent values and amounts; files without the new rules are byte-identical, and malformed entries are refused on load. |
| Gateway labelling | **Extended.** A value equal to a listed allowed value takes its trusted label, as a binding does. |
| Reference applications | **Extended.** A second application through a shared abstraction; the incident application is byte-identical. |
| Model targets | **Extended.** Anthropic Messages API; refusals unevaluable, configuration errors stop the run, no refusal fallback. |
| Approvals, provenance lattice, canonicalization, audit, config loading, benchmark scoring | Unchanged from RC14. |

## Found while releasing

- **The packaged research ledger had fallen behind.** `src/vais/data/research/` lacked every
  decision, finding and limitation added since rc14, because the packaging test compared three
  of seven files. It is synced, and the test now compares all seven.
- **The accounts-payable report still described attack-21 as an open gap.** Corrected.
- **The pilot's story-clustered bound divided the episodes but not the events.** Found by the
  frontier study's smoke test; the pilot's published numbers are unchanged.

## Open surfaces shipping unmitigated

**Per-invoice amounts within a budget (LIM-072).** Detected by the accounts-payable verifier
only. The monitor rule is planned for the next release.

**Frontier models under attack (FIND-067, FIND-068).** Untested in effect, since no available
attacker moved the model.

**Carried from RC14:**
- S13 on the library path;
- limits over several actions for stateless callers (LIM-035, LIM-044);
- model text (LIM-051);
- arguments without a trust requirement (LIM-048);
- state across machines (LIM-057).

## Validation and release gate

RC15 is releasable only after all of the following succeed on the final commit:

1. full source regression suite, with and without the `mcp` extra;
2. a mutation check of every fix and mechanism in this release;
3. default policy and invariant validation;
4. deterministic protected benchmark smoke test on the default and MCP paths;
5. wheel and sdist build plus isolated wheel installation with a probe for every change, with
   `experiments`, `website` and `campaigns` absent from both;
6. deterministic source ZIP reproduction, a test run from a fresh unzip, and SHA-256 manifest
   verification;
7. campaign harness self-test, and a campaign on each target with no `real` verdict;
8. tracked-tree secret and privacy scans, and a research-doctor result identical to a clean RC9
   tree;
9. clean GitHub CI across Python 3.11-3.14 on Windows and Linux;
10. annotated `v0.12.0rc15` tag and release assets built from the verified commit.

Results are recorded in `benchmarks/rc/v0.12.0rc15-release-review.json`. Passing these supports
only the recorded implementation and packaging result. It does not establish:
- universal prompt-injection resistance;
- production authorization-service readiness;
- external audit anchoring;
- enforcement against a frontier model under an attack that moves it.
