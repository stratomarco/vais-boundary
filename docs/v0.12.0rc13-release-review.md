# VAIS Boundary v0.12.0rc13 release review

Date: 2026-09-25

## Scope and decision rule

RC12 reviewed the monitor's edges. RC13 acts on what that review published: the monitor becomes
stateful, authority can expire and be withdrawn, a gateway takes the tools' credentials out of the
agent's reach, effects say how much is known about them, and two pre-registered studies test the
design against a stronger attacker and against a proposed control.

Every new mechanism is opt-in. With none of them configured, decisions are unchanged: both
benchmark snapshots regenerate with only the version, and the configuration hash that covers it,
moved. One defect was found and fixed in the monitor, one in the campaign harness, and thirteen
limitations were published.

RC13 adds new model evidence from the P1b-4 study, stated with its bounds below. The frozen RC7
evidence is carried unchanged. The review does not certify production readiness.

The tagged tree also contains `website/`, `campaigns/` and `experiments/`. None is part of the
library, all are absent from the wheel and the sdist, and `website/` is outside every gate check.

## Material findings, fixed

### FIND-056: a tool needing two kinds of approval could never be allowed

Each approval rule checked the store separately, so a tool requiring both an exact approval and a
threshold approval consumed the grant in the first check and found it spent in the second. It
failed closed, since nothing executed, but the human's approval was burned and the configuration
was unusable. Found while restructuring the approval path for the session ledger; approval is now
decided once and consumed at most once (DEC-045).

### FIND-060: the campaign's declared rules went stale

The release campaign on the policy target reported a `real` fault. The loader was right: P1b-6
added policy v6, and the campaign's declared postcondition still allowed versions 1 to 5, so a
correct load counted as a violation. The invariant target lacked the two new invariant types in
the same way. CI's campaigns had not generated a v6 policy. The declared sets are current, and a
test now fails whenever a loader accepts a version or type the campaign does not declare.

## New mechanisms

| Mechanism | What it does | Default |
|---|---|---|
| `SessionLedger` (P1b-3) | Enforces policy v5 `max_calls` in flight, makes contract-held approvals single-use, lets `monitor_mediated` check every effect against a recorded `ALLOW` | Off; a declared limit without a ledger is denied |
| Authority lifecycle (P1b-8) | Contract validity windows, grant TTL, `RevocationList`, a file-locked approval store, `TaskContract.delegate` that only narrows | Off |
| Gateway (P1b-5) | `vais gateway`: MCP over streamable HTTP, sole holder of upstream credentials, labels assigned at the boundary, operator-only approvals, reasons withheld from the agent | Separate process |
| Action origin (P1b-6) | Policy v6 `untrusted_origin`, `trusted_origin` invariant | Off, and not recommended as a default (DEC-056) |
| Effect confidence (P1b-7) | `requested`/`acknowledged`/`confirmed`/`contradicted`, profile `acknowledge` and `confirm`, `effect_confidence`, `verdict_basis` | Effects are `requested` unless something establishes more |

## New evidence

**P1b-4** (pre-registered): with qwen2.5-7b-instruct as a language-model attacker against four
local models, reasoning off and on, zero protected violations over 1,670 evaluable episodes in
seven arms, each arm's Wilson upper bound 1.6%. No detectable effect of reasoning in three
within-model pairs. Attacks produced policy-permitted actions the task did not need in 10% to 39%
of episodes, all reads, including a few searches naming another tenant's incident or a secret,
with tenant isolation and secret flow holding. Two reasoning-on arms gate-failed; one was re-run
as a registered follow-up (FIND-058, FIND-059, LIM-067).

**P1b-6** (pre-registered replay of RC7): an action-origin rule computed from everything visible
had an untrusted origin for every model action, clean or attacked, so it gates a tool and does not
detect an attack (FIND-057).

## Limitations published

LIM-055 to LIM-067. The ones that bound the new mechanisms most: the ledger and revocations live
in one process (LIM-055, LIM-056); cross-process consume-once holds on one machine (LIM-057); time
bounds are checked in ENFORCE only (LIM-058); the gateway's guarantee depends on a deployment VAIS
cannot inspect (LIM-060); action origin cannot discriminate (LIM-064); acknowledgement is the
server's own claim and confidence is reported, not enforced (LIM-065, LIM-066).

## Security-boundary review

| Review item | Bounded result |
|---|---|
| Approvals | **Changed.** Single-use with a ledger even without a store; grants can expire; the store holds across processes on one machine; FIND-056 fixed. |
| Reference monitor decision function | **Extended.** Validity, revocation and origin checks run first when configured; the ledger's limit check precedes approvals. Unchanged when none is configured, which the snapshots show. |
| Invariants | **Extended.** `monitor_mediated`, `trusted_origin` and `effect_confidence` added, none in the default set, which stays at seven. |
| Config loading | **Changed.** Policy v5 (`max_calls`) and v6 (`untrusted_origin`); profile `acknowledge` and `confirm`; gateway contract and configuration loaders, all strict. |
| Complete mediation | **Changed.** An architectural property behind the gateway under its deployment conditions (LIM-060); an assumption on the library path, checkable afterwards with `monitor_mediated`. |
| Decision-reason channel (S13) | **Mitigated at the gateway only**, where reasons are withheld from the agent by default (DEC-053). Unchanged on the library path. |
| Effects | **Changed.** An MCP effect carries a confidence; a contradicting reply or read-back is visible to VERIFY and in the audit. |
| Audit | **Changed.** The gateway keeps one hash-chained trail for every session. Still not externally anchored (LIM-037, LIM-038). |
| Campaign harness | **Fixed.** FIND-060. |
| Provenance lattice, canonicalization, benchmark scoring | Unchanged from RC12. |

## Open surfaces shipping unmitigated

**S13 on the library path.** Reasons returned by `ReferenceMonitor` and `MCPProtectedClient` are
unchanged; only the gateway withholds them.

**Stateless callers (LIM-035, LIM-044).** Without a `SessionLedger`, limits over several actions
and single use of a contract-held approval remain VERIFY-only.

**S15, model text and reasoning output (LIM-051).** Not mediated by any path.

**Arguments without a trust requirement (LIM-048).** Still carry the model's judgement inside the
policy; the origin rule is a human gate, not a fix (LIM-064).

## Validation and release gate

RC13 is releasable only after all of the following succeed on the final commit:

1. full source regression suite, with and without the `mcp` extra;
2. a mutation check of every fix and mechanism in this release;
3. default policy and invariant validation;
4. deterministic protected benchmark smoke test on the default and MCP paths;
5. wheel and sdist build plus isolated wheel installation with a probe for every change, with
   `experiments`, `website` and `campaigns` absent from both;
6. deterministic source ZIP reproduction, a test run from a fresh unzip, and SHA-256 manifest
   verification;
7. campaign harness self-test, and a campaign on each target with no `real` verdict;
8. tracked-tree secret and privacy scans, and a research-doctor result identical to a clean RC9
   tree;
9. clean GitHub CI across Python 3.11-3.14 on Windows and Linux;
10. annotated `v0.12.0rc13` tag and release assets built from the verified commit.

Results are recorded in `benchmarks/rc/v0.12.0rc13-release-review.json`. Passing these supports
only the recorded implementation and packaging result. It does not establish universal
prompt-injection resistance, production authorization-service readiness, external audit
anchoring, or any claim about frontier models.
