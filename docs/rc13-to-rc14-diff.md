# What changed between v0.12.0rc13 and v0.12.0rc14

Base: tag `v0.12.0rc13` (2026-09-25). Before this document and the release review were added:
23 commits, 97 files, **+21,453 / -261** lines, most of them recorded experiment summaries.

Every figure below is reproducible from the tags:

```
git diff --stat v0.12.0rc13..v0.12.0rc14
git rev-list --count v0.12.0rc13..v0.12.0rc14
```

## The headline

RC13 added a gateway; **RC14 checked it against the library and made what it holds durable.**
Replaying every recorded trace through the gateway found one defect, contract approvals ignored
beside an approval store (FIND-062), and one gap, authority an application creates mid-session
(LIM-068). Both are closed. Session state that lived in one process's memory, the ledger, the
revocation list and what a session has read, can now live in a locked file that survives a
restart and holds across processes on one machine. Four recorded gaps are closed, and the RC13
campaign reports that telling a language-model attacker the monitor's reasons made no detectable
difference.

**With nothing configured, nothing changes.** Both benchmark snapshots regenerated byte-identical
before the version bump, and after it the adaptive configuration hash, recomputed with the version
set back to rc13, reproduces rc13's value.

If you are reviewing for regression risk, the behavioural surface is 16 library files,
**+1,263 / -133**, and 40% of it is new code in three new modules:

| File | Lines | Why |
|---|---|---|
| `src/vais/gateway_replay.py` | +348 / -0 | Replaying recorded traces through the gateway (new; a verification tool) |
| `src/vais/durable.py`, `ledger.py`, `revocation.py` | +223 / -12 | File-backed session state shared by processes (`durable.py` new) |
| `src/vais/gateway.py`, `gateway_server.py` | +196 / -23 | State directory, revocations, call timeout, mints |
| `src/vais/audit.py` | +118 / -11 | Where a chain broke; verifying audit files |
| `src/vais/mcp.py` | +111 / -8 | Mints, effect kinds, call timeout |
| `src/vais/approvals.py` | +84 / -57 | Contract-approval use recorded in the store; the lock moved to `durable.py` |
| `src/vais/invariants.py`, `yaml_input.py`, `policy.py` | +56 / -8 | Inert invariants; one reader for every security file (`yaml_input.py` new) |
| `src/vais/monitor.py` | +20 / -8 | Contract approvals beside a store (FIND-062, DEC-060) |
| everything else in `src/vais` | +107 / -6 | Attacker feedback option, CLI commands, version |

Everything else is tests (+1,158, nine new modules), two regenerated snapshots, the research
ledger, the RC13 campaign and the gateway replay with their recorded outputs, and documentation.

## The monitor's decision function

One change, and only where it was wrong: with an approval store, an approval held in the contract
now counts, once per session, its use recorded in the store's file (FIND-062, DEC-060). Before,
it counted not at all. A first version recorded the use only in the in-memory ledger; review
showed a restarted gateway allowing the same pre-approved payment again, and it was replaced
before release. Everything else the monitor decides is unchanged, which the snapshots show.

## Found while releasing

Closing LIM-039 showed that a deeply nested security file also escaped as `RecursionError`, which
made the gateway's contract registry fail every lookup (FIND-066). The first version of the mint
created authority for tools a session's contract did not allow; the replay showed it as looser
labels, and minting is now limited to allowed tools.

## Still shipping unmitigated

S13 on the library path, limits for stateless callers (LIM-035, LIM-044), model text (LIM-051),
and arguments without a trust requirement (LIM-048). Durable state holds on one machine only.
See the release review.
