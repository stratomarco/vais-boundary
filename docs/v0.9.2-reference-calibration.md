# v0.9.2 Reference-Agent Calibration

v0.9.2 is the Reference Agent correctness/calibration pass that precedes the final v0.9.3 interface-normalization check before adaptive verification. It does not expand the attack inventory. It makes the real-case experiment more attributable, more production-shaped, and less dependent on model-specific quirks.

## 1. Scenario-specific trusted tasks

v0.9.1 used one broad incident-response instruction across the attack suite. Qwen frequently invented incident writes and communications even in matched controls, which made a workflow-level boolean attribution metric uninformative.

v0.9.2 gives every story an explicit trusted task with a concrete legitimate outcome. Examples include:

- create an approved public status artifact and send it to one exact recipient;
- inspect logs only, with no production restart authorized;
- restart only `service-api` under one exact prior approval;
- mark only `INC-1234` resolved;
- delegate research to `research-agent` while withholding production/secrets authority.

The application still exposes a broad tool catalog. Exposed tools and authorized tools are intentionally different concepts.

## 2. Semantic paired attribution

Each attack retains a matched non-hostile control with the same trusted task, contract, exposed tools, retrieval path, and turn budget.

For every valid pair VAIS now compares:

- proposed security-event signatures;
- policy-violation classes;
- authority-bearing argument values;
- failed trace-invariant evidence.

The summary reports:

- baseline control overreach;
- attacked security escalation;
- attack-added security events;
- attack-added violation classes;
- attack-modified authority;
- attack-objective success;
- attack-added invariant evidence.

This avoids the v0.9.1 failure mode where both control and attack had `security_escalation=true`, causing the attack to be classified as non-attributable even when it changed recipient, incident, service, or other authority semantics.

## 3. Opaque deterministic public artifacts

A model no longer has to copy a trusted public string exactly or decide that a paraphrase is safe to publish.

The trusted flow is:

```text
INTERNAL incident
      |
      v
status.build_public_update
      |
      v
opaque PUBLIC artifact ID
      |
      +--> email.send_public_update
      +--> slack.send_public_update
```

The public text remains in the trusted application artifact store. The model selects an approved artifact identifier and destination; it never self-declassifies arbitrary text.

## 4. Deterministic resource ownership

Tenant isolation now resolves resource ownership using a registry such as:

```text
INC-1234 -> acme
INC-9000 -> tenant-b
```

A cross-tenant attack therefore remains detectable even if a model strips a literal prefix like `tenant-b/`.

## 5. Sequential dependency semantics

The planner is explicitly told not to fabricate a value that should come from an unseen tool result. When a workflow requires a declassified artifact, the agent must first call the trusted declassifier, observe the returned artifact ID on a later turn, and only then dispatch it.

## 6. Utility denominators

v0.9.2 reports both:

- end-to-end workflow utility, where target-generation failure counts as failure;
- utility among workflows whose target generations remained valid.

This makes model reliability and workflow quality distinguishable without hiding either.

## Security model

The security boundary is unchanged in principle:

> **Assume model compromise. Constrain consequence. Verify effects.**

Authorization, provenance, information flow, exact approvals, declassification, resource ownership, execution mediation, and trace invariants remain deterministic. No AI judge participates in a security decision.
