# v0.10.2 — Research Evidence Integrity

v0.10.2 is an evidence-base correctness patch. It does not change the v0.9.3 reference-system security boundary, the v0.10 adaptive verifier, policy semantics, protected invariants, declassification, tenant enforcement, exact approvals, or terminal security reward.

## Why this patch exists

Historical VAIS releases intentionally retain copies of source files, summaries, JSONL outputs, wheels, checksums and audit artifacts. A research archive should preserve those copies for provenance, but it must not silently count each copy as a new scientific experiment.

v0.10.2 therefore distinguishes:

- artifact instances from unique artifact content hashes;
- experiment records from content-addressed experiment groups;
- observation records from content-addressed observations;
- evidence-link instances from logical evidence references.

The raw instance counts remain useful for provenance. The content-addressed counts are the safer inventory for future reporting.

## Research doctor

`vais research-doctor` audits an existing SQLite evidence base without modifying it:

```powershell
vais research-doctor --db .\research\db\vais-research.sqlite
```

The doctor reports:

- duplicate artifact instances and duplicate-content groups;
- content-addressed experiment and observation counts;
- logical evidence references rather than copy-inflated link rows;
- unresolved evidence references;
- expected external manuscripts separately from unexpected missing project evidence;
- SHA-256 mismatches;
- supported claims with no resolved evidence;
- findings with no resolved evidence;
- partially unresolved supported claims;
- version-level artifact/experiment/observation coverage.

`--strict` returns exit code 2 only for integrity problems that require attention. A source explicitly marked `artifact_expected_external` may remain absent from a public repository without making the evidence base fail integrity checks.

## Bootstrap audit evidence

The source release now carries canonical copies of three historical project audit artifacts under `research/bootstrap/`:

- `VAIS-v0.8.1-qwen-v080-mcp-audit.json`
- `VAIS-v0.8.1-gemma-v080-mcp-audit.json`
- `VAIS-v0.10.0-targeted-verifier-audit.json`

These are project-generated audit evidence referenced by canonical claims/findings. They are bundled so those links do not depend on an arbitrary local download location.

The capstone manuscript and author essays remain intentionally external. Their expected SHA-256 hashes are recorded in `research/knowledge/sources.yaml`; users can add their local copies with repeated `--root` arguments when building the evidence base.

## Interpretation rule

Do not write, for example, "VAIS contains 427 experiments" merely because the archive has 427 experiment records. A historical copy of an identical artifact is provenance, not an independent experimental repetition.

Future reports should prefer language such as:

> The archive contains N experiment records across M content-addressed experiment groups, with duplicate historical copies retained for provenance.

Even content-addressed experiment groups are an inventory concept, not automatically a count of statistically independent trials. Independence remains a property of the experimental design and must be justified separately.
