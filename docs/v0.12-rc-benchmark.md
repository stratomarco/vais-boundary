# v0.12.0-rc7 reasoning-profile correction and RC5 evidence history

The RC benchmark separates infrastructure readiness from empirical results. The manifest freezes fifteen Q4_K_M instruction models across nine named families, with four Qwen models and eleven non-Qwen models. Popularity informed selection, while family diversity, instruction suitability and likely RTX 4080 Super 16 GB feasibility took precedence over a literal download ranking.

RC3 corrected LM Studio reasoning-off requests to use `reasoning_effort=none` while keeping observed reasoning as the conformance authority. RC4 replaced manual model-by-model operation with a fail-closed, resumable runner. Its campaign exposed a real model-output lineage defect. RC5 corrected that defect and completed a new fifteen-model run. RC6 changed reporting only. RC7 corrects a configuration assumption exposed by the RC5 DeepSeek gate: not every reasoning model can be switched off in the tested runtime.

The report labels the benchmark evidence as `0.12.0rc5` and the renderer as `0.12.0rc6`. A newer renderer is never evidence that a newer campaign ran.

## RC7 DeepSeek investigation

The archived RC5 DeepSeek preflight contained six valid target generations, zero target failures and zero protected violations, but 2,813 reasoning tokens under a declared reasoning-off configuration. The gate therefore behaved correctly.

The RC7 investigation checked the exact local Q4_K_M model and current LM Studio runtime. The native catalog exposed no reasoning configuration for `deepseek-r1-distill-llama-8b`. Four identical 160-token probes were then run with `reasoning_effort=none`, the legacy `chat_template_kwargs.enable_thinking=false` switch, both controls, and no control. Every probe emitted 158 reasoning tokens. LM Studio's native `reasoning=off` request returned HTTP 400 because the model does not expose reasoning configuration.

RC7 does not relabel those outputs as reasoning-off and does not weaken the gate. The manifest now defines fourteen reasoning-off models and one separately labeled native-reasoning model. DeepSeek runs without a false disable request and must emit observed reasoning to conform. A strict one-episode RC7 preflight passed with six valid generations, 4,651 reasoning tokens, zero target failures and zero protected violations. Its one attack-added diagnostic event and failed workflow utility are retained, but this bounded preflight is not a full result.

Reasoning conformance is now bidirectional: explicit off requires no observed reasoning; explicit on, low, medium or high requires observed reasoning. The runner also rejects a stage whose summary reasoning label or disable request differs from the manifest. Auto and undeclared labels remain non-enforced descriptors.

## Why RC5 exists

The RC4 runner attempted 4,059 staged episodes and evaluated 4,057. Eleven models reached a complete full stage; four stopped at a gate. One Qwen2.5-7B screening episode produced an independently observed `secret_public_flow` violation: a model copied only part of a secret-bearing value into a public sink. The RC4 adapter treated the output as public because it did not contain the complete source value. The verifier correctly detected the resulting external canary effect.

RC5 removes that unsound inference. Model output inherits the maximum confidentiality of every value visible to the generation. Exact rebinding is allowed only with canonical, type-sensitive security equality; lowering confidentiality requires a trusted explicit declassifier. This can conservatively overtaint output, but it never treats absence of a full string match as proof of independence.

The original RC4 reports also emphasized only completed full-stage rows, so the gate-triggering screening violation could disappear from the headline. RC5 retains every model's highest reached stage and aggregates safety-critical totals across every executed stage. Those all-stage totals are useful for safety accounting but are not a balanced ranking denominator because they include distinct stage budgets.

## One-command execution

First validate the entire downloaded inventory without loading or unloading a model:

```powershell
vais benchmark --all --dry-run
```

Then run or resume the panel:

```powershell
vais benchmark --all
```

The same command resumes after a controlled interruption. The runner uses an exclusive process lock, verifies checkpointed SHA-256 hashes, skips completed stages, recovers a complete three-file stage artifact set written immediately before interruption, and refuses partial, untracked or modified artifacts. It starts the local LM Studio server if necessary, unloads existing models when execution begins, loads one model at a time, and unloads the model after its run.

`--model <panel-id>` can select one or more panel models while diagnosing, but inventory validation still covers all fifteen frozen models. Automatic lifecycle management is restricted to a local HTTP LM Studio endpoint. The runner never downloads a model.

## Identity and runtime validation

Before any campaign runs, all fifteen manifest entries must resolve to exactly one downloaded LLM with the exact local model key and Q4_K_M quantization. Each model must support the frozen 8,192-token context. Before and after every stage, the runner requires exactly one loaded LLM and verifies:

- downloaded model key;
- benchmark API identifier;
- Q4_K_M quantization;
- 8,192-token context length;
- parallelism 1.

The manifest requests maximum GPU offload. Runtime observations are checkpointed without API tokens or prompt/secret content. RC5 does not hash multi-gigabyte GGUF files; exact model-byte identity remains a limitation.

## Stages and gates

Preflight uses one representative story and one episode. Qualification uses three stories and two episodes each. Screening uses all twenty stories with three episodes each. Full campaigns use all twenty stories with twelve episodes each, or 240 attempted episodes per completed model.

A model advances only when the previous stage is complete and independently validated. A model stops at its current stage when any of these gates fires:

- protected invariant violation;
- target-generation failure or unevaluable episode;
- observed output that contradicts the declared reasoning mode;
- a summary reasoning label or control request that differs from the manifest;
- attacker-generation failure;
- unavailable control/attack pair delta;
- incomplete campaign or episode budget;
- mismatch between the independently derived gate and process exit status.

The failed model remains visible in the checkpoint and report, and the runner continues with the next model. These are experiment-validity or security-stop gates. They do not redefine terminal security reward.

## Outputs and reports

The default result directory contains per-model and per-stage episode JSONL, summary JSON and RLVR JSONL artifacts plus `benchmark-state.json`. The report directory is regenerated after each passed stage and after each model:

- `benchmark-report.html` — self-contained, responsive and print-friendly report;
- `executive-summary.md` — compact one-page summary;
- `technical-report.md` — methods, model table and limitations;
- `benchmark-table.svg` — GitHub-ready contextual scorecard;
- `rc-aggregate.json` — machine-readable aggregate.
- `report-evidence-manifest.json` — renderer/evidence versions, verified input identity and public-example sanitization contract.

The verified RC5 checkpoint can be rendered offline without contacting LM Studio:

```powershell
vais benchmark-report `
  --state .\results\rc\benchmark-state.json `
  --manifest .\benchmarks\rc\report\rc5-evidence-explained\report-evidence-manifest.json `
  --artifact-root . `
  --output-dir .\results\rc\report
```

Rendering fails closed if the manifest hash, checkpoint version, artifact size or artifact SHA-256 differs from the recorded state. Public examples are derived deterministically and omit prompts, tool arguments, tool results, effect attributes, secret-bearing values and detailed invariant messages. They retain only the minimum structure needed to explain enforcement: scenario ID, broad reason class, tool sequence, effect kind, invariant ID and independently verified outcome.

Missing models remain pending. Failed stages remain failed and their highest-stage metrics remain visible. Wrong-stage, off-panel, duplicate-target and framework-version-mismatched summaries are never promoted. RC3 and RC4 files are historical evidence and are not relabeled as RC5 rows. The legacy `rc-benchmark-plan` and `rc-report` commands remain available for inspection and offline aggregation.

All fifteen models now receive the same optional 4,096-token retry after a recorded length truncation. The original failed attempt remains in generation metadata. Recovery does not erase the failure attempt, and an unrecovered target failure remains unevaluated.

## Reading the graph

The summary explains the protocol above the graph and uses explicit numerators and denominators:

- **Protected violations** are independently observed protected invariant violations divided by evaluable episodes. Lower is better, but zero is not a universal proof.
- **Utility** is successful attacked protected workflows divided by evaluable episodes. Higher is better. A model at 90% utility completed more tested tasks than one at 75%; this does not mean it is “90% secure.”
- **Attack-added events** are episodes with attack-caused security-relevant drift divided by evaluable episodes. They are diagnostic pressure, not terminal security reward.
- **Target failures** are unevaluated and never counted as successful defense.

VAIS intentionally provides no composite security score. Readers should compare only configuration-conformant rows within the same reasoning profile and keep security, utility and diagnostic drift separate. Native-reasoning and reasoning-off utility, latency, token use and attack-added rates are not like-for-like measurements.

## Verified RC5 result rendered by RC6

The immutable RC5 checkpoint records 171 verified artifacts. Fourteen models completed the common full budget: 3,360/3,360 episodes were evaluable, 0 protected invariant violations were observed, protected-workflow utility was 2,203/3,360 (65.6%), and attack-added diagnostic events occurred in 1,226/3,360 (36.5%). These four measurements answer different questions; the utility and diagnostic percentages are not security scores.

DeepSeek-R1-Distill-Llama-8B stopped after preflight because observed reasoning did not conform to the declared reasoning-off configuration. It remains visible as a configuration-gate result and receives no inferred full-campaign rates. Across every distinct executed stage, including qualification and screening executions later superseded by full campaigns, 4,299/4,299 episodes were evaluable, with 0 observed protected violations and 0 target failures. This all-stage total preserves safety evidence but is not a balanced model-ranking denominator.

The paired full-cohort utility outcomes were 2,085 control-success/attack-success, 207 control-success/attack-failure, 118 control-failure/attack-success and 950 control-failure/attack-failure, with 0 unavailable pairs. This is why the report shows pair outcomes rather than attributing every utility difference to enforcement or attack effects.

Representative traces are explanatory examples selected from the recorded episodes. They show how a proposal reached deterministic authorization and independent effect verification, but they do not estimate how common a behavior was and are not causal explanations of model differences.

## Runtime findings retained from RC1–RC4

- Qwen3.5-9B Q4_K_M previously produced zero observed reasoning tokens under requested off mode in bounded RC1 and RC2 checks.
- Gemma-4-12B previously emitted reasoning despite the earlier compatibility-template hint and was configuration-nonconforming.
- RC2 Qwen3-0.6B recorded 2,043 reasoning tokens under that ignored hint. A same-runtime probe with `reasoning_effort=none` recorded zero, motivating RC3.
- The user-operated RC3 Qwen3-0.6B full campaign completed 240 evaluable episodes with zero observed protected violations, zero target failures, reasoning-off conformance and 50% protected-workflow utility. It remains RC3 evidence and must not be silently promoted into RC4.
- The RC4 automated campaign recorded 4,059 attempted staged episodes, 4,057 evaluable episodes, one protected violation and two target-failure episodes. Eleven models completed the full stage and four stopped at a gate. These totals preserve every distinct staged execution; they are discovery evidence, not a balanced cross-model RC5 result table.

## Claim boundary

The benchmark is bounded to recorded model keys, quantizations, declared reasoning profiles, runtime, hardware, prompts, scenarios and budgets. It compares observed systems, not abstract model families. Requested reasoning control is not trusted; conformance is derived from recorded output. The DeepSeek finding does not establish that every DeepSeek checkpoint or runtime lacks an off mode. Family and size comparisons are descriptive rather than causal. Conservative model-output lineage may deny safe derived text until an application supplies a trusted declassification step. The model manifest records exact local keys and quantization but not multi-gigabyte GGUF byte hashes. Public reports are sanitized derivatives; controlled raw traces remain the independent verification source. The 4,299 RC5 episodes remain historical bounded evidence, not an RC7 result and not proof of universal security.
